# Security Policy

## Scope

This repository primarily contains documentation, Markdown content, configuration files, and supporting scripts. It does not contain a versioned software product.

Security concerns may nevertheless arise from:

- Scripts or automation contained in the repository
- Commands or instructions that could result in unsafe behaviour
- Accidental exposure of credentials, secrets, tokens, or sensitive information
- Dependencies used by scripts or automation
- Links or references that could direct users to unsafe resources
- Repository workflows, configuration, or permissions

## Reporting a Security Issue

Please do not report suspected security vulnerabilities through a public GitHub issue, discussion, or pull request.

Where available, use GitHub's **Private Vulnerability Reporting** feature.

If private vulnerability reporting is not enabled, contact the repository maintainers through the organisation's approved security reporting channel.

Please include:

- A description of the issue
- The affected file, script, workflow, or documentation
- Steps required to reproduce or demonstrate the issue
- The potential security impact
- Any suggested mitigation, if known

## Secrets and Sensitive Information

Do not commit passwords, API keys, access tokens, connection strings, certificates, private keys, or other sensitive information to this repository.

If you believe a secret has been exposed, report it privately and treat the credential as compromised.

## Security Updates

As this repository does not maintain versioned software releases, security issues are normally addressed in the default branch.

Consumers should use the latest content from the repository where practical.
